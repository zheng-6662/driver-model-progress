## 总结论：三种划分里，event_split 不合理（有硬泄漏），subject_hash 口径对但测试集太小，recording_hash 最可用但覆盖不均

**你的采集背景**（这是评判基准）：18 名被试、2025-09-26~28 三天、每人**单日一次会话**连续跑 1~9 趟（79 条 recording）；事件由失稳规则触发（|ay|≥1.3 / |roll_rate|≥0.05）；工况 3 类：直道 68%、下坡弯道 21%、普通弯道 12%；被试事件量差 20 倍（zx 116 vs xst 5）。

| 协议 | 实测结构 | 判定 |
| --- | --- | --- |
| event_split（事件级随机，v3xx 曲线线同族） | 18/18 被试、73/79 recording 跨集合 | **不合理：有字节级克隆泄漏** |
| recording_hash_split | recording 不跨集合，但 test 只覆盖 9/18 被试，6 人从不进 val/test | 基本合理，仅支持"个性化/时段外"口径 |
| subject_hash_split | test 仅 3 人（cwh/lxy/rjy），val 里 zx 一人占 44% | 口径正确但撑不起"跨被试泛化"结论 |

**最重要的发现（新问题，之前未记录）**：事件池里有 153 组"同 recording + 同锚点时刻"的克隆事件（多峰拆分产物），event_split 下 93 组跨集合——**107 对 train↔test/val 样本的 650 维输入和全部未来标签逐位完全相同**。这不是"相关"，是 test 里混进了 train 的原样副本。实测影响：v345 的 test 中 54/232（23%）事件被波及，这些事件 RMSE 均值 0.373 vs 干净事件 0.491，**v345 的 test all=0.4575 偏乐观约 6%**。另外即使去掉克隆，同 recording 相邻事件锚点差 p25 只有 6.4 秒，而滚动线风格窗口取锚前 60 秒，窗口重叠依然会高估性能。

对已有结论的影响：R380 的 strict pass 方向性保留（recording/subject 两协议天然免疫克隆，三协议同过才算过），但含 event_split 的平均数字（19.30%）需去重后复核。

**建议（按优先级）**：
1. 事件池去重：同 recording 且锚点差 ≤0.5s 的组只留一个，重建后重跑 R377 复刻 + R380；
2. event_split 停用，或加"同 recording ±60s 排他缓冲"后只作诊断；
3. 论文的跨被试口径改 **LOSO-18 或 6 折×3 人轮转**，报"被试级均值±被试间方差"——固定 3 人 test 方差根本没法评估；
4. 表述上声明"每被试单日采集，被试效应与当日状态混淆"——这是采集设计固有限制，划分解决不了，只能声明。
