默认不要为非重大策略调整或常规执行细节单独请示用户；像是否写入项目日志这类既定流程，直接执行即可。

**Why:** 用户希望减少不必要的来回确认，把注意力留给真正重要的策略分叉，而不是被例行执行问题打断。

**How to apply:** 后续在本仓库中，日志写入、常规检查、低风险实现、标准验证、已有规则要求的记录动作等都直接做；只有在涉及重大策略调整、非显然后果或高风险动作时再停下来询问。
