When analyzing or improving the driver-response / thesis model in this repository, do not rely only on repo-internal runs and scripts. Bring in relevant literature as part of the diagnosis and recommendation process, especially around driver reaction delay/latency, driving habit differences, individual heterogeneity, and other human-factor effects.

**Why:** The user wants model conclusions and next-step changes to be grounded in domain knowledge rather than only repository-internal trial-and-error.

**How to apply:** For substantial model-direction or protocol-diagnosis work, compare observed failure modes against literature-backed explanations and use those explanations to shape recommendations, ablations, and task redefinitions.
