Claude 和 Codex 的协作不应只是“Claude 思考，Codex 执行”。用户明确希望双方 agent 都参与思考、查错、review 计划与结果，形成双向审查与交叉验证。

**Why:** 单向分工虽然清晰，但不足以充分利用双方优势；用户更看重双 agent 的互相质疑、互相补洞和交叉检查能力。

**How to apply:** 后续设计协作流程时，应优先采用双向评审结构，例如 Claude 先出方案或命令简报、Codex 先挑错补充并审查是否适合执行，再由 Codex 执行，执行后 Claude 再复核，必要时再回到 Codex 做二次审查，而不是把 Codex仅当作纯执行器。
 这在实验、脚本修改、批处理任务上默认适用：先审查 brief/命令，再执行。
